# Submitting

**One submission per team. Submit by 4:00 PM to get a demo slot.**

**[Open the submission form](https://faithtechhub.typeform.com/to/nIdH7FbF)**

## What the form asks

| Field | Notes |
|---|---|
| Team name and members | |
| Your track | 1, 2 or 3 |
| One-sentence pitch | Your direction: "We help [audience] to [do the central atomic action] by [the technology you've created]." |
| Public repo link | On your own GitHub account, or in FaithTech's org (see below) |
| Demo video | Optional. A 60 to 90 second walkthrough ([how](demo-video.md)) |
| Continue, hand off or stop? | After today, will your team keep building it, hand it to someone else, or stop? Any answer is fine. Be honest. |

## Your repo

Use a public repo on your own GitHub account. If your team wants its repo in FaithTech's GitHub
org, ask Travis or Jesse to add you, and have your GitHub username ready.

- [ ] The repo is **public**.
- [ ] A README that follows [`templates/TEAM-README.md`](../templates/TEAM-README.md).
- [ ] A license file. MIT is fine.
- [ ] The README says **how to run it**, so someone who is not on your team can.
- [ ] **Test data only.** No real church, pastor or person data. See
      [ground rules](ground-rules.md).
- [ ] No API keys or passwords in the repo or its history.

**Built without code?** Make a repo anyway. Put a README in it with a link a judge can open on a
phone (a prototype, Figma, a doc), shared as "anyone with the link can view".

## New to GitHub?

One teammate with a free account is enough: on github.com choose **New repository**, make it
public, then **Add file**, **Upload files**. Stuck? Find a mentor well before 4:00.

## After 4:00

Demos run from 4:15: 3 minutes per team, then 2 minutes of questions. See [judging](judging.md).
Your repo stays public so the work can be picked up later. That is stewardship, not a claim on
your IP.
