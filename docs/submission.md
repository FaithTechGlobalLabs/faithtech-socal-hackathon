# Submitting

**One submission per team. Due 4:00 PM.** You can submit early and keep pushing. Edit your
submission any time with your contact email.

## The form

On the event hub: **<https://faithtech-socal-hackathon.vercel.app/#submit>**

| Field | Notes |
|---|---|
| Team name | |
| Track | 1, 2 or 3 |
| Members | Everyone on the team |
| Public GitHub repo URL | Must be public |
| Short write-up | A few sentences: what you built and who it is for |
| Demo video | Optional |
| Contact email | Use the same email to edit your submission later |

## Repo checklist

- [ ] The repo is **public**.
- [ ] A README that follows [`templates/TEAM-README.md`](../templates/TEAM-README.md).
- [ ] A license file. MIT is fine.
- [ ] The README says **how to run it**, so someone who is not on your team can.
- [ ] **Test data only.** No real church, pastor or person data. See
      [ground rules](ground-rules.md).
- [ ] No API keys or passwords in the repo or its history.

## Optional: a walkthrough video

Ask Claude to click through your prototype and record a walkthrough. Put the link in your README
and on the form. A phone video of your screen works too.

## New to GitHub?

One teammate with a free account is enough. You can upload files from the website with
**Add file**, then **Upload files**. Stuck? Find a FaithTech mentor well before 4:00.

## After 4:00

Demos follow: 90 seconds of working prototype, then what God did. See [judging](judging.md).
Your repo stays public so the work can be picked up later. That is stewardship, not a claim on
your IP.
