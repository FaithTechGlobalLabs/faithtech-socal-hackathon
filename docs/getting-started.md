# Getting started

From laptop to first result in about 15 minutes. Any skill level.

## 1. GitHub account (2 min)

Make a free account at [github.com](https://github.com) if you do not have one. One person per
team needs it; everyone can have one.

## 2. Create a public repo (2 min)

1. On GitHub, choose **New repository**.
2. Name it for your team. Set it to **Public**.
3. Tick **Add a README** and choose an **MIT** license.
4. Add teammates under Settings, then Collaborators.

Want your repo in FaithTech's GitHub org instead? Ask Travis or Jesse to add you, and have your
GitHub username ready.

Public is a rule: it lets someone pick the work up later. See
[the README](../README.md#why-the-code-lives-on-github).

## 3. Pick a tool (3 min)

Use what you already know. Any of these work, and so does any other AI tool you like.

| Tool | Good for |
|---|---|
| **Claude.ai** in the browser ([claude.ai](https://claude.ai)) | Teams that do not code |
| **Claude Code** ([claude.com/claude-code](https://claude.com/claude-code)) | Building in a folder on your laptop |
| **Another AI tool** you already use | Staying fast with what you know |

Ask a FaithTech mentor if setup is slow. Nobody should lose the afternoon to an install.

## 4. Your first prompt (5 min)

Open your track folder: [1](../tracks/1-mobile-church-onboarding/),
[2](../tracks/2-testimony-sharing/), [3](../tracks/3-first-30-days/). Give your AI tool the
track README and the files in its `test-data/` folder, then ask something like:

> Here is the problem for our track and some made-up test data. Build the smallest version that
> works end to end, using only this test data. Tell me how to run it, and what you were unsure
> about.

Run what it gives you. Fix one thing. Repeat.

## 5. Push (3 min)

Commit and push to your repo. Do it again every hour or so. Never put API keys in the repo, and
keep to [test data only](ground-rules.md).

## If you do not write code

You are needed. Write test cases, read every output and say what is wrong, write the words on
the screen, pray with the team and run the demo. You can also build: describe what you want in
plain words.
